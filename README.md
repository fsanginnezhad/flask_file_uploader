# آپلودر فایل سازمانی (Flask)

یک سرویس آپلود فایل سازمانی مبتنی بر Flask با احراز هویت JWT، پنل مدیریت کامل برای ادمین، و یک رابط کاربری ساده (PWA) برای کاربران عادی روی موبایل.

## ویژگی‌ها

- 🔐 احراز هویت با JWT (بدون ثبت‌نام عمومی — کاربران فقط توسط ادمین ساخته می‌شن)
- 📁 هر کاربر پوشه‌ی مخصوص به خودش رو داره
- ✅ محدودیت فرمت و حجم فایل، هم به‌صورت پیش‌فرض سراسری و هم قابل تنظیم برای هر کاربر به‌طور جداگانه
- 🗓️ نام‌گذاری فایل روی دیسک بر اساس تاریخ و ساعت شمسی (جلالی)
- 👤 نام نمایشی فارسی برای هر کاربر (مستقل از یوزرنیم)
- 🛠️ پنل مدیریت کامل: مدیریت کاربران، پوشه‌ها، فایل‌ها، و تنظیمات پیش‌فرض سراسری
- 📱 صفحه‌ی آپلود به‌شکل PWA — قابل نصب روی صفحه‌ی اصلی گوشی
- ⏱️ خروج خودکار بعد از ۱۵ دقیقه بی‌کاری، و با بسته‌شدن تب/مرورگر

## پشته‌ی فنی

Flask · Flask-SQLAlchemy · Flask-JWT-Extended · SQLite · جاوااسکریپت خام (بدون فریمورک فرانت‌اند)

## ساختار پروژه

```
flask-file-uploader/
├── app/
│   ├── auth/          # لاگین
│   ├── files/         # آپلود فایل توسط کاربر عادی
│   ├── admin/         # مدیریت کاربران، تنظیمات، پوشه‌ها، فایل‌ها
│   ├── main/          # سرو کردن صفحات HTML (لاگین، آپلود، پنل)
│   ├── models.py      # User, File, GlobalSettings
│   ├── utils.py       # احراز هویت، نام‌گذاری فایل
│   └── config.py
├── templates/         # login.html, upload.html, admin.html
├── static/            # CSS، JS، مانیفست PWA، آیکون‌ها
├── run.py
└── requirements.txt
```

## نصب و راه‌اندازی

```bash
git clone <آدرس-ریپازیتوری-شما>
cd flask-file-uploader

python3 -m venv venv
source venv/bin/activate      # ویندوز: venv\Scripts\activate

pip install -r requirements.txt

cp .env.example .env
# فایل .env رو باز کن و SECRET_KEY / JWT_SECRET_KEY رو با مقادیر رندوم واقعی جایگزین کن:
python3 -c "import secrets; print(secrets.token_hex(32))"
```

### ساخت اولین کاربر ادمین

چون ثبت‌نام عمومی نداریم، باید اولین ادمین رو از ترمینال بسازی:

```bash
export FLASK_APP=run.py      # ویندوز: set FLASK_APP=run.py
flask create-admin admin رمز_دلخواه
```

### اجرا

**توسعه (dev):**
```bash
python run.py
```

**پروداکشن (روی سرور، پشت Gunicorn):**
```bash
gunicorn -w 4 -b 127.0.0.1:5000 run:app
```

سپس مرورگر رو باز کن روی `http://127.0.0.1:5000` (یا آدرس سروری که تنظیم کردی).

## صفحات

| مسیر | برای کی | توضیح |
|---|---|---|
| `/` | همه | صفحه‌ی مشترک لاگین؛ بعد از ورود بر اساس نقش ریدایرکت می‌شه |
| `/upload` | کاربر عادی | آپلود فایل، قابل نصب به‌عنوان PWA |
| `/panel` | ادمین | پنل مدیریت تک‌صفحه‌ای با تب‌های کاربران/تنظیمات/پوشه‌ها/آپلود |

## مستندات API

همه‌ی درخواست‌های محافظت‌شده به هدر زیر نیاز دارن:
```
Authorization: Bearer <access_token>
```

### عمومی
| Method | Path | توضیح |
|---|---|---|
| POST | `/auth/login` | ورود، برمی‌گردونه `access_token` |
| POST | `/files/upload` | آپلود یک یا چند فایل (`multipart/form-data`, کلید `files`) |
| GET | `/files/my-files` | لیست فایل‌های خود کاربر |

### ادمین (نیاز به `is_admin=True`)
| Method | Path | توضیح |
|---|---|---|
| GET/POST | `/admin/users` | لیست / ساخت کاربر |
| PUT/DELETE | `/admin/users/<id>` | ویرایش / حذف کاربر |
| PATCH | `/admin/users/<id>/promote` | تغییر نقش ادمین بودن |
| GET/PUT | `/admin/settings` | تنظیمات پیش‌فرض سراسری (حجم و فرمت مجاز) |
| GET | `/admin/folders` | لیست پوشه‌ها (کاربران) به‌همراه تعداد فایل |
| GET | `/admin/folders/<user_id>/files` | فایل‌های یک کاربر خاص |
| PUT/DELETE | `/admin/files/<file_id>` | تغییر نام / حذف فایل |
| POST | `/admin/upload` | آپلود توسط ادمین (برای خودش یا با `target_user_id`) |

## نکات امنیتی

- توکن JWT سمت کلاینت در `sessionStorage` نگه داشته می‌شه (نه `localStorage`) تا با بسته‌شدن تب/مرورگر پاک بشه.
- بعد از ۱۵ دقیقه عدم فعالیت کاربر (کلیک، اسکرول، تایپ)، خروج خودکار انجام می‌شه.
- اعتبار خود توکن سمت سرور محدود به ۱ ساعته (به‌عنوان لایه‌ی پشتیبان امنیتی).
- صفحات حساس (`/`, `/upload`, `/panel`) با هدر `Cache-Control: no-store` سرو می‌شن تا با دکمه‌ی back مرورگر، نسخه‌ی کش‌شده نشون داده نشه.
- **قبل از استفاده‌ی واقعی، حتماً `SECRET_KEY` و `JWT_SECRET_KEY` رو تو `.env` با مقادیر رندوم واقعی عوض کن** — مقادیر پیش‌فرض فقط برای توسعه‌ی محلی هستن.

## نکات پیاده‌سازی

- فایل‌ها روی دیسک با نام یکتای مبتنی بر تاریخ/ساعت شمسی ذخیره می‌شن (مثل `1405-06-14_04-52-06-149_0862b7.pdf`)؛ نام اصلی فایل جدا در دیتابیس نگه‌داری می‌شه.
- هر کاربر می‌تونه محدودیت حجم و فرمت اختصاصی داشته باشه؛ اگه تنظیم نشده باشه، از پیش‌فرض سراسری استفاده می‌شه.
- کاربران فایل‌های خودشون رو مستقیماً از روی سرور می‌بینن (نه از طریق سایت)؛ مسیر هر کاربر: `uploads/<username>/`.
- چون از `db.create_all()` (نه Alembic/Flask-Migrate) استفاده می‌شه، با هر تغییر تو `models.py`، دیتابیس باید از نو ساخته بشه (`rm app.db` و اجرای دوباره‌ی `flask create-admin`) مگر اینکه بعداً Migration واقعی اضافه بشه.

## توسعه‌های آینده

- افزودن Flask-Migrate برای مدیریت تغییرات دیتابیس بدون نیاز به حذف کامل
- مکانیزم refresh token برای enforce دقیق‌تر timeout سمت سرور
